## Purpose

This document researches whether an accumulator-based status approach can
represent revocation and suspension for future F6 CWT/COSE adapters without
exposing claim values, holder identifiers, credential identifiers, witness
material, epoch material, or correlation handles to Skynet core.

It does not select:

```text
accumulator construction
witness format
revocation authority
epoch publisher
integrity mechanism
status artifact format
cryptographic dependency
issuer
verifier
wallet
transport
```

No accumulator implementation, fixture, ALN artifact, adapter, or Rust source
is generated by this research document.

## Fail-Closed Rule

```text
Missing witness, stale epoch, unavailable authority, unavailable status artifact,
unverifiable provenance, or unresolved freshness policy must never result in
Active.

The adapter returns Unavailable or another separately approved closed result.
The core declines presentation and records only a content-minimized reason code.
```

## Core Normalization

Regardless of accumulator family, the adapter returns only:

```text
Active
Expired
Suspended
Unavailable
Unrecognized
```

Interpretation:

```text
Active = status evaluation is current, witness is valid, freshness policy is
satisfied, and no governing status artifact identifies suspension or revocation.

Expired = current validated time is after normalized expiry.

Suspended = governing status evaluation identifies temporary non-usability.

Unavailable = witness unavailable, stale epoch, unavailable authority,
unavailable artifact, unverifiable provenance, or failed freshness policy.

Unrecognized = credential reference is outside the approved status domain or
the adapter cannot identify a governing status representation.
```

Not-before failure remains a separate non-usability condition pending
data-contract approval and must decline presentation with a closed reason code.
